# BTC Swing Alpha

سیستم سیگنال‌دهی **swing trading** برای بیت‌کوین — ترکیب آلفای یادگیری ماشین، فیچرهای میکرواستراکچر سبک، و تشخیص رژیم اقتصادی ماکرو.

> ⚠️ این ابزار برای **تحلیل و بک‌تست** است، نه توصیه‌ی سرمایه‌گذاری. خروجی‌ها سیگنال تحلیلی‌اند؛ تصمیم معاملاتی با خودِ کاربر است.

---

## این سیستم چه کار می‌کند؟

زنجیره‌ی کامل از داده‌ی خام تا تصمیم:

```
داده‌ی صرافی‌ها (Kraken/Coinbase/Binance)  ┐
داده‌ی ماکرو بازاری (DXY/VIX/Gold/...)     ┼─→ ادغام و اجماع
                                           │
   ┌───────────────────────────────────────┘
   ↓
مهندسی فیچر  →  تشخیص رژیم  →  مدل ML  →  استراتژی  →  بک‌تست
(تکنیکال +     (رکود/رونق)     (آموزش +    (ترکیب      (کارمزد +
 میکرو +                       ذخیره +     سیگنال +    لغزش +
 ماکرو)                        بازآموزی)   ریسک)       معیارها)
   ↓
تصمیم لحظه‌ای + «قیاس» با تاریخچه‌ی بک‌تست  →  API  →  داشبورد
```

**سه لایه‌ی سیگنال که با هم ترکیب می‌شوند:**

1. **آلفای ML** — مدل LightGBM روی ۵۰+ فیچر آموزش می‌بیند تا جهت آینده‌ی قیمت (صعود/خنثی/نزول) را در افق چند کندلی پیش‌بینی کند.
2. **میکرواستراکچر سبک** — فشار خرید/فروش، جریان نقدینگی جهت‌دار، و اسپرد بین صرافی‌ها — همه از OHLCV استنتاج می‌شوند (بدون نیاز به order book).
3. **رژیم ماکرو** — از DXY، VIX، طلا، بازده اوراق و S&P یک «امتیاز رژیم» ساخته می‌شود که مشخص می‌کند در فاز رونق هستیم یا رکود. این امتیاز اندازه‌ی پوزیشن را تعدیل می‌کند: در رکود محافظه‌کارتر، در رونق با اطمینان بیشتر.

cd btc-swing-alpha

## اجرا

### ۱) خط فرمان (سریع‌ترین راه برای تست)

```bash
# اجرای کامل زنجیره + گزارش بک‌تست برای تایم‌فریم روزانه
python scripts/run.py pipeline --tf 1d

# تایم‌فریم ۴ساعته، با بازآموزی اجباری مدل
python scripts/run.py pipeline --tf 4h --retrain

# فقط تصمیم لحظه‌ای (سبک)
python scripts/run.py live --tf 1d

# هر دو تایم‌فریم
python scripts/run.py all
```

### ۲) بک‌اند API + داشبورد

```bash
# ترمینال اول: راه‌اندازی سرور
python -m btcalpha.api.server
```

سپس فایل `frontend/index.html` را در مرورگر باز کن. داشبورد خودش به `localhost:8000` وصل می‌شود و هر ۶۰ ثانیه به‌روز می‌شود.

## نکات روش‌شناختی مهم

**ضد نشت داده (data leakage):** رایج‌ترین اشتباه در ML مالی. این‌جا رعایت شده:
- تقسیم train/valid/test کاملاً **زمانی** است، نه تصادفی.
- فیچرها فقط از گذشته ساخته می‌شوند؛ برچسب از آینده.
- در بک‌تست، تصمیمِ کندل t با قیمت بسته‌شدن t گرفته می‌شود اما ورود با قیمت **باز شدن t+1** اجرا می‌شود.
- داده‌ی ماکرو با forward-fill هم‌تراز می‌شود (هر کندل فقط آخرین مقدار در دسترس را می‌بیند).

**مدل خودش را ذخیره می‌کند:** بعد از آموزش، وزن‌ها + scaler + متادیتا در `storage/models/` نوشته می‌شوند. اجرای بعدی مدل را بارگذاری می‌کند، نه آموزش دوباره. بازآموزی دوره‌ای (پیش‌فرض هر ۷ روز) خودکار است و از طریق دکمه‌ی داشبورد یا `--retrain` هم قابل‌فعال‌سازی است.

**«قیاس» چیست؟** سیستم تصمیم لحظه‌ای را با تاریخچه‌ی بک‌تست مقایسه می‌کند: آیا معاملات هم‌جهت در گذشته سودده بوده‌اند؟ این رژیم در گذشته چه عملکردی داشته؟ خروجی یک «حکم» است (قوی/متوسط/ضعیف) که در داشبورد نمایش داده می‌شود.

## داده‌ی واقعی در برابر شبیه‌سازی‌شده

اگر `ccxt` و `yfinance` نصب باشند و اینترنت در دسترس باشد، سیستم **داده‌ی واقعی** می‌کشد. اگر نه (مثلاً هنگام تست آفلاین)، با **داده‌ی شبیه‌سازی‌شده‌ی واقع‌نما** کار می‌کند تا بتوانی منطق را ببینی.

> در حالت شبیه‌سازی، اعداد بک‌تست **بی‌معنی‌اند** — فقط ثابت می‌کنند موتور درست محاسبه می‌کند. برای ارزیابی واقعی، حتماً روی داده‌ی واقعی اجرا کن.

این رفتار با `data.allow_synthetic_fallback` در `config.yaml` کنترل می‌شود. اگر می‌خواهی در نبود داده‌ی واقعی سیستم خطا بدهد (نه شبیه‌سازی)، آن را `false` کن.

## تنظیمات کلیدی (`config/config.yaml`)

| بخش | چه چیزی را کنترل می‌کند |
|-----|------------------------|
| `data.exchanges` | کدام صرافی‌ها، کدام منبع اصلی |
| `data.history` | چند کندل تاریخی برای آموزش |
| `features.horizons` | افق پیش‌بینی (چند کندل جلوتر) |
| `features.label_threshold_pct` | آستانه‌ی صعود/نزول برای برچسب |
| `model.retrain.every_n_days` | فاصله‌ی بازآموزی خودکار |
| `strategy.regime_multipliers` | ضریب اندازه‌ی پوزیشن در هر رژیم |
| `strategy.stop_loss_atr` / `take_profit_atr` | حد ضرر و سود بر حسب ATR |
| `strategy.kelly_fraction` | کسر کِلی برای position sizing |
| `backtest.fee_pct` / `slippage_pct` | کارمزد و لغزش شبیه‌سازی |

## محدودیت‌ها و هشدار صادقانه

- این یک **چارچوب مهندسی‌شده** است، نه یک سیستم سودده تضمین‌شده. کیفیت سیگنال در نهایت به کیفیت داده و وجود «edge» واقعی بستگی دارد، نه به کد.
- بک‌تست خوب ضامن عملکرد آینده نیست (overfitting، تغییر رژیم بازار، هزینه‌های پنهان).
- مدل پیش‌فرض ساده نگه داشته شده تا قابل‌فهم باشد؛ برای استفاده‌ی جدی باید فیچرها، اعتبارسنجی متقاطع زمانی، و تحلیل حساسیت را عمیق‌تر کنی.
- قبل از هر استفاده‌ی واقعی، حتماً روی داده‌ی واقعی و دوره‌های مختلف بازار آزمایش کن.
